## 2. 프로젝트 구조와 데이터 흐름

```text
FRED 금융데이터
  → 수집·점수 계산 파이프라인 (A·B·C 담당)
  → Supabase PostgreSQL (저장)
  → Render FastAPI (저장된 데이터 조회)
  → Render Static Site (이 frontend/의 대시보드 화면)
```

브라우저는 Supabase DB에 직접 접속하지 않습니다. 프론트엔드가 FastAPI를 호출하며, 점수·위험단계·시장별 기여도는 **API가 제공한 값**을 표시합니다. 프론트엔드에서 점수나 위험단계를 다시 계산하지 않습니다.

**두 Render 주소는 서로 다릅니다.** 웹화면에는 `-1.onrender.com`을 사용하고, `API_BASE`에는 `-1`이 없는 FastAPI 주소를 사용합니다. 기존 시험용 Vercel 페이지는 최종 운영 주소가 아닙니다.

| 경로 | 내용 |

초기 ZIP에는 별도 `tests/` 및 `docs/` 자료가 들어 있었으나, 해당 파일들은 현재 팀 GitHub의 `frontend/`에 함께 반영된 것으로 간주하지 않습니다. 원본 ZIP의 회귀 테스트 실행 결과가 필요하면 자료를 별도로 공유하거나 팀원과 저장 위치를 합의해야 합니다.

## 4. 로컬 실행 (Windows VS Code 기준)

VS Code 터미널에서 팀 저장소 최상위 경로(`team7-stress-dashboard/`)에 위치한 후:

```cmd
cd frontend
python -m http.server 5500
```

브라우저에서 http://localhost:5500/ 을 엽니다. Python의 `python` 명령이 인식되지 않으면 `py -m http.server 5500`을 사용합니다. 웹서버 종료는 **해당 터미널에서 `Ctrl + C`**입니다.

이 프론트엔드는 HTML·CSS·JavaScript 정적 웹이므로 별도의 Python 가상환경, npm 설치, 데이터베이스 비밀번호가 필요하지 않습니다. `index.html`을 `file://`로 직접 열기보다는 로컬 HTTP 서버를 사용합니다.

## 5. 실제 API / 샘플 전환

`app.js` 상단 설정:

```javascript
const CONFIG = {
  USE_SAMPLES: false,
  API_BASE: "https://team7-stress-dashboard.onrender.com",
  // 나머지 기존 설정 유지
};
```

`USE_SAMPLES: false`가 기본 운영 설정입니다. 개발·시연 목적으로는 코드 수정 없이 주소창의 쿼리로 일시 전환할 수 있습니다.

| 주소 뒤에 붙일 값 | 동작 |
|---|---|
| 쿼리 없음 | 기본 설정대로 **실제 API 데이터** 표시 |
| `?source=api` | 실제 API 데이터 강제 표시 |
| `?source=samples` | 테스트용 샘플 JSON 강제 표시(실제 데이터가 아님) |
| `?source=samples&case=zero` 등 | 샘플 예외 시나리오 시험 |

지원하는 샘플 예외 경우: `zero`, `nostage`, `empty`, `stale`, `nohistory`, `error`, `slow`. 예외 테스트는 샘플 모드에서만 사용하며, 운영 화면·발표 자료에서 샘플과 실데이터를 혼동하지 않습니다.

## 6. 화면 기능

- 종합 스트레스 점수(0~100), 위험단계, 과거 대비 백분위 표시
- 4개 시장(주식·외환·금리·신용)의 점수·기여도와 동시 스트레스 시장 수 표시
- 종합 점수 추이: `1개월` / `3개월` / `1년` / `전체`, `차트` / `표` 전환
- 5개 지표: 원/달러 환율(`DEXKOUS`), 미국 10년물 금리(`DGS10`), S&P500(`SP500`), VIX(`VIXCLS`), Baa 회사채-10년물 금리차(`BAA10Y`)
- 지표별 현재값·관측일·변화량, 지표 행 선택 시 과거 관측값 상세 표시
- 스트레스 산식·위험단계 기준·FRED 데이터 출처 표시
- 조회 실패·데이터 지연·결측 등 예외 상태 안내

주요 API는 `/scores/latest`, `/scores?from=&to=`, `/indicators`, `/indicators/{code}/observations?from=&to=`, `/health`입니다. 상세 응답 형식은 저장소의 `docs/api/` 규격서를 따릅니다.

## 8. 데이터 및 운영 유의사항

- **종합 점수의 기준일**은 5개 지표를 함께 계산할 수 있는 공통 기준일입니다. **각 지표의 최신 관측일은 서로 다를 수** 있습니다.
- `/health`의 `정상 갱신` 표시는 시스템이 정의한 신선도 기준을 충족한다는 의미이며, '오늘자 시세'를 뜻하지 않습니다. API의 `STALE_DAYS` 기본값은 통합 노트 기준 **10일**입니다.
- 스트레스 점수 **0**은 유효한 계산 결과일 수 있으며, 미수집·결측 `null`과 구분합니다. 화면에서 `null`은 `—` 등으로 표시하고 임의로 0으로 대체하지 않습니다.
- 위험단계는 종합점수 자체가 아니라 과거 분포의 백분위에 따라 정해집니다(정상/주의/경계/위험). 프론트엔드는 API의 `stage`를 그대로 사용합니다.
- 과거 비교 기간은 **관측 가능한 과거 기간(최소 2년·최대 10년)**으로 안내합니다. 일부 지표의 가용 데이터 시작일이나 계산 시작일 때문에 '전체' 차트의 시작점이 다를 수 있습니다.
- Render 무료 환경에서는 백엔드 휴면 해제 때문에 첫 요청이 지연될 수 있습니다. 잠시 기다린 후 새로고침하며, 장시간 실패 시 `/health` 및 C 담당자의 Render 상태를 확인합니다.
- 공개 코드·README·GitHub 커밋에 `DATABASE_URL`, `FRED_API_KEY` 등 비밀값을 넣지 않습니다.
- 화면의 지표는 과거 시장 불안 수준을 설명하기 위한 것이며 미래 예측이나 매수·매도 신호가 아닙니다.

## 9. 코드 변경 및 Render 배포 절차

1. GitHub `main`의 최신 내용을 가져온 뒤 **별도 작업 브랜치**에서 `frontend/` 파일만 수정합니다.
2. 브라우저 로컬 실행, 화면 점검, `git diff`로 변경 범위를 확인합니다.
3. 변경 파일만 커밋·푸시하고 `main` 대상으로 Pull Request를 생성합니다.
4. C(태현님) 검토·승인 후 병합합니다. (팀에서 사전 승인한 경우 D가 병합 가능.)
5. `main` 반영 후 Render 정적 사이트의 자동 배포 완료를 확인하고 **최종 주소**에서 재검증합니다.

**문서만 변경한 경우** 별도의 Vercel 수동 업로드나 프론트엔드 재개발은 필요 없습니다. README도 팀 코드의 일부이므로, 단순 메신저 파일 공유만 하지 말고 **`frontend/README.md`를 GitHub PR로 반영**해 문서와 실제 코드를 일치시킵니다.
